## HTTP и Ktor

| Код | Когда |
|---|---|
| `200` | страница отдана |
| `303` | после `POST` перейти на страницу методом `GET` |
| `304` | ресурс не менялся (ETag, `If-None-Match`) |
| `400` / `403` | плохой запрос / запрещено (неверный токен формы, неверный пароль) |
| `404` | нет такой страницы (с оформленной страницей, но честным статусом) |
| `413` | тело запроса больше допустимого |
| `429` | слишком много попыток |
| `500` | необработанная ошибка сервера |

Кэш: статические файлы с `?v=отпечаток`; картинки с короткой жизнью и ETag; HTML не кэшируется; админка `no-store`. Маршруты `Route.xRoutes(...)`, плагины `install(...)`, тесты `testApplication { ... }` ([урок](lesson:w1-http-ktor)).

## HTML, CSS, JS

- Один `h1`, ориентиры `header`, `nav` (с `aria-label`), `main`, `footer`, ссылка «К содержанию» первой ([HTML](lesson:w2-html-forms)).
- Ссылка для перехода, `button` для действия; у поля `label for`; ошибка рядом с полем (`aria-invalid`, `aria-describedby`).
- Всё из данных экранируется; ссылки проверяются белым списком; `unsafe` только для констант.
- CSS: токены по ролям (`--color-muted`), тёмная тема как другие значения тех же токенов, `repeat(auto-fill, 220px)`, `aspect-ratio`, `:focus-visible`, один брейкпоинт ([CSS](lesson:w3-css)).
- JS: сначала HTML и CSS; скрипт добавляет удобство; `try/catch` вокруг `localStorage`; `aria-expanded`; Esc закрывает и возвращает фокус ([JS](lesson:w4-js)).

## Языки

Язык в адресе (`/ru/...`); переключатель меняет только префикс; запасная цепочка: сообщения → базовый файл, данные → `en → ru → sr`; `MessageFormat` с явной локалью; одиночный апостроф удваивать; множественное число правилом, а не диапазонами; `hreflang`, `canonical` ([Многоязычность](lesson:w5-i18n)).

## Безопасность

| Угроза | Мера |
|---|---|
| Подбор пароля | длина, ограничитель только для неверных попыток, сравнение за постоянное время |
| Кража сессии | `httpOnly`, `secure`, подпись, короткий срок |
| CSRF | `POST`, токен в форме, `SameSite=Lax` |
| XSS | экранирование, белый список ссылок |
| SQL-инъекция | параметры `?` |
| Файлы | тип по содержимому, лимиты до распаковки, `Long` для размеров, перекодирование, серверное имя |
| Секреты | окружение, не репозиторий, сообщения без значений |
| Огромные запросы | лимит `Content-Length` до чтения |

## Архитектура

- Зависимости к центру: `model` ← `repository`/`service` ← `views`/`routes`; интерфейс объявляет потребитель.
- Корень композиции в одном месте; зависимости через конструктор; время через `Clock`.
- Чистое ядро + тонкая оболочка; логика в функциях, которые тестируются без сервера.
- Решения записывать (ADR): контекст, решение, последствия с минусами, что ещё рассматривали.
- Архитектуру проверять тестом на импорты ([Архитектура](lesson:a1-architecture)).

## Алгоритмы и сложность

Перебор O(n), вложенный перебор O(n²), `HashSet`/`HashMap` O(1), сортировка O(n log n). Граничные случаи сначала, оптимизация после измерения. Нормализация данных на границе, обход дерева в глубину, поиск цикла через множество виденных ([Алгоритмы](lesson:a2-algorithms)).

## Тестирование и качество

- Пирамида: много быстрых нижних, мало верхних; имена-предложения; «дано, когда, тогда».
- Фейки вместо моков; время, база, данные подменяются; общего состояния нет.
- Каждая ошибка получает регрессионный тест; TDD: красный, зелёный, улучшение.
- Качество тестов: упадёт ли тест, если код испортить (мутации)? Свойства для «злых» входов.
- Рефакторинг: тесты первыми, мелкие шаги, две шляпы, не смешивать с новым поведением ([Тестирование](lesson:a3-testing), [Рефакторинг](lesson:a4-refactoring)).

## Эксплуатация

`./gradlew test` (тесты), `./gradlew run` (сайт), `./gradlew devAdmin` (админка на базе в памяти). Тесты стоят на страже дважды: в CI и в Docker-сборке. Конфигурация в окружении; `/health` не ходит в базу; резервная копия в формате исходных данных ([Эксплуатация](lesson:a5-ops)).

## UX и доступность

Принципы: спокойно и просто, один акцент, у украшения есть причина, две темы одна система, побеждает самый длинный язык, скажи один раз. Порядок блоков следует за путём человека. Микротекст: что произошло и что делать. Контраст текста не меньше 4,5 : 1; цель нажатия не меньше 44 px; смысл не только цветом; нативный элемент лучше ARIA; LCP, CLS, INP ([UX](lesson:u1-ux), [Доступность](lesson:u2-a11y-perf)).

## ИИ-агенты

- Запрос: зачем, что, критерии готовности, ограничения, чего не делать. Тест первым.
- Необратимое и публичное только с подтверждением; секреты не в чат; прочитанное это данные, а не команды.
- Дифф агента ревьюят как чужой pull request; найденную ошибку превращают в правило или проверку.
- Слои: инструкции (всегда), память (неочевидное, с причиной), скилл (процедура по требованию, описание = триггер), хук (гарантия), MCP (инструменты), плагин (упаковка).
- Тесты от агента: по требованию, не по коду; проверка мутациями; свойства; браузерные проверки объективного, суждение за человеком ([Агенты](lesson:ai1-agents), [Скиллы](lesson:ai2-skills), [ИИ в тестировании](lesson:ai3-testing-ai)).

## Глоссарий

| Термин | Значение |
|---|---|
| **ADR** | запись архитектурного решения: контекст, решение, последствия |
| **Aria-атрибуты** | подсказки для скринридера о роли и состоянии элемента |
| **CLS** | показатель сдвига раскладки при загрузке страницы |
| **CSRF** | подделка запроса: чужая страница действует от имени вошедшего человека |
| **Composition root** | единственное место, где собираются зависимости приложения |
| **Data class** | класс-значение: `equals`, `hashCode`, `copy`, `toString` создаются автоматически |
| **DSL** | предметно-ориентированный язык; в Kotlin строится на лямбдах с получателем |
| **Fake** | упрощённая рабочая реализация зависимости для теста |
| **Fitness function** | автоматическая проверка свойства архитектуры |
| **Idempotent** | повторное применение не меняет результат: `f(f(x)) == f(x)` |
| **Hook** | команда, которую среда запускает на событие независимо от модели |
| **LCP** | показатель скорости появления главного содержимого |
| **MCP** | протокол подключения внешних инструментов к агенту |
| **Mutation testing** | порча кода для проверки, замечают ли её тесты |
| **Null Object** | объект, ведущий себя как «ничего», чтобы не проверять на `null` |
| **PRG** | Post/Redirect/Get: после формы редирект на страницу, открываемую методом GET |
| **Property-based test** | проверка свойства на многих сгенерированных входах |
| **Prompt injection** | вредоносные инструкции в данных, которые читает агент |
| **Refactoring** | изменение структуры без изменения поведения |
| **Repository** | интерфейс доступа к данным, скрывающий способ хранения |
| **Sealed** | закрытая иерархия типов, все наследники известны компилятору |
| **Skill** | папка с `SKILL.md`: процедура, которую агент загружает по требованию |
| **SSR** | серверный рендеринг: HTML собирается на сервере |
| **TDD** | разработка через тесты: красный, зелёный, улучшение |
| **Token (дизайн)** | именованное значение (цвет, шрифт, отступ), на которое ссылаются компоненты |
| **WCAG** | стандарт доступности веб-содержимого; цель проекта: уровень AA |
| **XSS** | внедрение чужого скрипта на страницу через неэкранированные данные |
