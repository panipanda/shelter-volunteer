# Финальный экзамен

Тридцать вопросов по всему курсу, по пять в шести блоках. Отвечайте без подглядывания: ошибка здесь дешёвая, а разбор после ответа покажет, какой урок стоит перечитать. Итоговый результат считается внизу страницы. Нужно не «набрать баллы», а увидеть слабые места.

Правила: в вопросах с пометкой «верных ответов несколько» нужно выбрать **все** верные варианты. Любой вопрос можно пройти заново кнопкой «Ещё раз».

:::quiz Блок 1. Kotlin
Q: Что выведет код?

```kotlin
val name: String? = null
println(name?.length ?: -1)
```
- [ ] `null`
- [ ] `0`
- [x] `-1`
- [ ] Исключение `NullPointerException`
E: `?.` вернёт `null` для всей цепочки, а `?:` подставит `-1`. Урок: [Основы Kotlin](lesson:k1-basics).

Q: `data class Cat(val id: Int, val name: String)`. Что верно для `Cat(1, "A") == Cat(1, "A")` и `Cat(1, "A") === Cat(1, "A")`?
- [ ] `false` и `false`
- [x] `true` и `false`
- [ ] `true` и `true`
- [ ] `false` и `true`
E: `==` сравнивает поля у `data class`, а `===` сравнивает ссылки на объекты. Урок: [Моделирование](lesson:k3-modeling).

Q: Что делает `generateSequence(first) { it.plusWeeks(1) }.first { it !in cancelled }`?
- [ ] Строит список всех будущих дат.
- [x] Лениво идёт по неделям и останавливается на первой дате, которой нет в отменённых.
- [ ] Бросает исключение, если дата отменена.
- [ ] Работает только с `Set`.
E: Ленивая последовательность и `first` вычисляют только нужное. Урок: [Коллекции](lesson:k2-collections).

Q: Зачем нужен `sealed interface`, когда `when` по нему используется как выражение?
- [ ] Чтобы запретить `null`.
- [x] Компилятор знает все наследники и требует обработать каждый, поэтому новый вид без обработки не компилируется.
- [ ] Чтобы ускорить `when`.
- [ ] Чтобы наследников можно было добавлять из других модулей.
E: Закрытая иерархия превращает расширение модели в подсказки компилятора. Урок: [Моделирование](lesson:k3-modeling).

Q: Верные утверждения о корутинах и многопоточности в проекте (верных ответов несколько).
- [x] `Mutex` пропускает обработку фото по одной, чтобы не исчерпать память.
- [x] `AtomicInteger` защищает счётчик ожидающих попыток входа.
- [ ] `@Volatile` делает `generation++` атомарной операцией.
- [ ] `delay` блокирует поток на время паузы.
E: `@Volatile` даёт видимость, но не атомарность `++`; `delay` приостанавливает корутину, не блокируя поток. Урок: [Ошибки и конкурентность](lesson:k5-errors-concurrency).
:::

:::quiz Блок 2. Данные и веб
Q: Почему `documentJson` включает `encodeDefaults = true`?
- [ ] Чтобы JSON получался короче.
- [x] Чтобы сохранённые записи не зависели от умолчаний в коде: изменение умолчания не изменит смысл старых данных.
- [ ] Это требует PostgreSQL.
- [ ] Чтобы ускорить чтение.
E: Явная запись всех полей делает документ самодостаточным. Урок: [Данные](lesson:k6-data).

Q: Какое решение подходит, когда после успешной отправки формы нужно показать другую страницу?
- [ ] Ответить `200` и нарисовать страницу в ответ на `POST`.
- [x] Ответить `303 See Other` с `Location`, чтобы обновление страницы повторило безопасный `GET`.
- [ ] Ответить `404`.
- [ ] Ответить `301`.
E: Post/Redirect/Get защищает от повторной отправки при обновлении. Урок: [HTTP и Ktor](lesson:w1-http-ktor).

Q: Что означает `?v=1a2b3c4d` в адресе стилей?
- [ ] Версию Kotlin.
- [x] Отпечаток содержимого файла: при изменении файла адрес меняется и кэш браузера не отдаёт старое.
- [ ] Номер пользователя.
- [ ] Язык страницы.
E: Это приём cache busting через хэш содержимого. Урок: [HTTP и Ktor](lesson:w1-http-ktor).

Q: Что защищает от XSS в страницах проекта (верных ответов несколько).
- [x] kotlinx.html экранирует текст по умолчанию.
- [x] Адреса ссылок из текстов проходят проверку белым списком (`https://`, `http://`, `mailto:`, `/`, `#`).
- [ ] Проверка `required` в полях формы.
- [ ] Скрытие адреса `/admin`.
E: Экранирование и белый список работают на сервере. `required` — удобство браузера, а скрытие адреса не защита. Урок: [HTML на сервере](lesson:w2-html-forms).

Q: Почему тёмная тема в CSS реализована как те же токены с другими значениями?
- [ ] Так короче.
- [x] Вёрстка не дублируется: компоненты ссылаются на токены (`--color-bg`, `--color-ink`), а тема подменяет их значения.
- [ ] Браузеры не умеют иначе.
- [ ] Так тема работает без JavaScript.
E: Одна система с двумя наборами значений проще поддерживать и проверять на контраст. Урок: [CSS](lesson:w3-css).
:::

:::quiz Блок 3. Безопасность, языки, архитектура
Q: Почему пароль и CSRF-токен сравниваются через хэши и `MessageDigest.isEqual`?
- [ ] Так читаемее.

- [ ] Хэш защищает от SQL-инъекций.
- [ ] Строки нельзя сравнивать через `==`.
E: Это защита от атаки по времени. Урок: [Безопасность](lesson:w6-security).

Q: Фото, загруженное в админке, проходит проверки. Какая из них защищает от «бомбы распаковки»?

- [ ] Перекодирование в JPEG.
- [ ] Серверное имя файла.
E: Маленький файл может объявить огромные размеры; декодирование заняло бы гигабайты. Урок: [Безопасность](lesson:w6-security).

Q: В `messages_sr.properties` нет ключа. Что покажет сербская страница?

Q: Что такое инверсия зависимостей на примере `CatService`?
- [ ] Сервис вызывает файлы напрямую для скорости.
- [x] Сервис зависит от интерфейса `CatRepository`, а реализации (файл, база) подстраиваются под него.
- [ ] Репозиторий вызывает сервис.
- [ ] Сервис создаёт репозиторий сам.
E: Высокоуровневый код определяет нужный ему интерфейс. Урок: [Архитектура](lesson:a1-architecture).

Q: Что показал подсчёт импортов в проекте?
- [ ] Архитектура идеальна.
- [x] Маршруты читают `SiteContentRepository` напрямую, а репозитории импортируют типы из `service`: описанная и реальная архитектуры немного расходятся.
- [ ] `model` зависит от `routes`.
- [ ] Слоёв нет.
E: Измерять и замечать расхождения полезнее, чем верить схеме. Урок: [Архитектура](lesson:a1-architecture).

:::quiz Блок 4. Алгоритмы, тесты, рефакторинг
Q: Для чего последний `flush()` после цикла в разборщике гайда?
- [ ] Для очистки памяти.
- [x] Последний блок, не закрытый пустой строкой, иначе остался бы в буфере и потерялся.
- [ ] Чтобы вернуть пустой список.
- [ ] Это стиль.
E: Конец файла такой же разделитель, как пустая строка. Урок: [Алгоритмы](lesson:a2-algorithms).

Q: Как обнаруживается цикл в родителях узлов меню?
- [ ] Рекурсией без ограничений.
- [x] Идём вверх по родителям, запоминая виденные узлы; повторная встреча означает цикл.
- [ ] Сортировкой.
- [ ] Подсчётом узлов.
E: `HashSet.add` возвращает `false` при повторе. Урок: [Алгоритмы](lesson:a2-algorithms).

Q: Почему в тестах проекта используют фейк репозитория, а не мок?
- [ ] Моки запрещены.
- [x] Фейк проверяет результат и переживает рефакторинг; мок привязывает тест к тому, как вызывается зависимость.
- [ ] Фейк всегда быстрее.
- [ ] Мок нельзя написать на Kotlin.
E: Тестируют «что получилось», а не «как это сделано». Урок: [Тестирование](lesson:a3-testing).

Q: Чем опасно покрытие строк как единственная метрика?
- [ ] Ничем.
- [x] Оно показывает, что код выполнялся, а не что результат проверялся; тест без `assert` даёт то же покрытие.
- [ ] Оно считает только Kotlin.
- [ ] Оно замедляет сборку.
E: Силу проверок показывают мутации и ревью. Урок: [Тестирование](lesson:a3-testing).

Q: Рефакторинг `validatePets` прошёл при неизменных тестах. Что это значит?
- [ ] Тесты не нужны.
- [x] Поведение, зафиксированное тестами, не изменилось; структура улучшилась, что и есть цель рефакторинга.
- [ ] Код стал быстрее.
- [ ] Тесты слабые.
E: Неизменные зелёные тесты подтверждают сохранение поведения. Урок: [Рефакторинг](lesson:a4-refactoring).

## Что делать с результатом

- **Выше 85%.** Отлично. Выберите расширения из [итогового проекта](lesson:capstone) и попробуйте их.
- **65–85%.** Хорошо. Вернитесь к урокам, где были ошибки (ссылка есть в разборе каждого вопроса), и пройдите их квизы заново.
- **Ниже 65%.** Вернитесь к частям, где ошибок больше всего, и повторите вместе с живым кодом: запускайте примеры, меняйте их, ломайте и чините.

Сделайте паузу и повторите экзамен через неделю: то, что вспоминается с усилием, запоминается лучше.
