# Многоязычность: ru, en, sr

Сайт говорит на трёх языках: русском, английском и сербском (латиницей). Это не «добавить переводы в конце»: многоязычность влияет на адреса, на модель данных, на дизайн (сербский и русский длиннее английского), на правила склонения и даже на то, как поисковики видят страницы. В проекте она решена так, что добавить четвёртый язык значит добавить значение в `enum`, файл сообщений и переводы в данных.

После урока вы сможете:

- спроектировать адреса и переключатель языков;
- объяснить цепочку запасных языков для сообщений и для данных;
- правильно форматировать сообщения с подстановкой и склонением (и знать, где это ломается);
- подключить многоязычные метаданные для поисковиков.

## Язык в адресе

Язык — первая часть пути: `/ru/cats`, `/en/cats`, `/sr/cats`. Этот выбор лучше альтернатив:

| Способ | Минусы |
|---|---|
| Определять по заголовку `Accept-Language` | одна страница с разным содержимым: кэшам и поисковикам тяжело; нельзя отправить ссылку «на английскую версию» |
| Хранить в cookie | то же самое, плюс не работает без cookie |
| **Префикс в адресе (проект)** | адрес однозначно определяет страницу; ссылкой можно поделиться; поисковики видят три страницы |

Адрес `/` перенаправляет на язык по умолчанию (`/ru`). А переключатель языка меняет только префикс и оставляет остальное:

```run
enum class Lang(val code: String) { RU("ru"), EN("en"), SR("sr") }

fun switchTo(target: Lang, current: Lang, path: String) =
    "/${target.code}${path.removePrefix("/${current.code}")}"

fun main() {
    println(switchTo(Lang.EN, Lang.RU, "/ru/cats/felix"))
    println(switchTo(Lang.SR, Lang.RU, "/ru"))
}
```

```output
/en/cats/felix
/sr
```

Это работает, потому что **структура адресов во всех языках одинакова**: `/cats/felix` везде, а не `/кошки/феликс` в русской версии. Слаг кошки строится из её английского имени (мы писали `petSlug` в первом уроке: кириллицу он превращает в номер), поэтому адрес не зависит от языка страницы.

:::note Страница, которой нет на языке
Разделы, которые собирает админка, могут существовать не на всех языках: статья может быть написана только по-русски. Тогда ссылка переключателя на отсутствующую версию ведёт на главную, а в `hreflang` перечисляются только существующие языки. Это решение из `docs/decisions.md`: лучше честное «такой страницы здесь нет», чем ссылка в никуда.
:::

## Сообщения интерфейса: ResourceBundle

Тексты интерфейса лежат в файлах `src/main/resources/i18n/`:

```text
messages.properties       (the base file: English)
messages_ru.properties
messages_en.properties    (empty on purpose, see below)
messages_sr.properties
```

```properties
# messages_ru.properties
cat.age.unknown=Возраст неизвестен
nav.submenu=Подразделы: {0}
```

Файл `messages_en.properties` в проекте **пустой намеренно**: английские тексты лежат в базовом файле. Но сам файл нужен: `ResourceBundle` находит его для локали `en` раньше, чем смотрит на язык JVM по умолчанию. Без него `/en` на машине с русской локалью по умолчанию подхватил бы `messages_ru`. Тест `MessagesTest` проверяет именно это («English messages do not depend on the JVM default locale»).

Функция `messagesFor(locale)` вызывает стандартный `ResourceBundle.getBundle("i18n.messages", Locale...)`, а маленькое расширение `t(key, args)` подставляет аргументы. Если в сербском файле нет ключа, JVM берёт его **из родительского файла** (базового, английского). Эту цепочку можно воспроизвести в десяти строках:

```run
class Bundle(private val messages: Map<String, String>, private val parent: Bundle? = null) {
    fun get(key: String): String = messages[key] ?: parent?.get(key) ?: error("missing key: $key")
}

fun main() {
    val base = Bundle(mapOf("nav.cats" to "Cats", "nav.help" to "How to help"))
    val sr = Bundle(mapOf("nav.cats" to "Mačke"), parent = base)
    println(sr.get("nav.cats"))
    println(sr.get("nav.help"))
}
```

```output
Mačke
How to help
```

Непереведённая фраза показывается по-английски, а не как «nav.help» и не как пустое место. Для сайта, который переводят по частям, это важное свойство: он всегда выглядит завершённым.

### Две цепочки запасных языков

В проекте есть **две** независимые цепочки, и важно не смешивать их:

- **Сообщения интерфейса** (`ResourceBundle`): язык страницы, затем базовый английский.
- **Данные** (`LocalizedText.forLocale`): язык страницы, затем английский, затем русский, затем сербский, иначе пустая строка. Мы писали её в уроке про [моделирование](lesson:k3-modeling): `valueFor(locale) ?: en ?: ru ?: sr ?: ""`.

Для данных админка **сообщает о пробелах**: список показывает, у какой записи нет сербского перевода, но не запрещает сохранить. Идея: пусть сайт опережает переводчика, а не ждёт его.

### Подстановка и апострофы

Сообщения с аргументами форматирует `MessageFormat`: `nav.submenu=Подразделы: {0}`. Две ловушки, которые проект уже встретил:

1. **Локаль форматирования.** Статический `MessageFormat.format(pattern, args)` форматирует числа в локали машины. На сервере «1234567» в русском контексте превращался бы в зависимости от настроек хостинга. Поэтому `t()` создаёт `MessageFormat(pattern, bundle.locale)` явно (комментарий в `Messages.kt`).
2. **Одиночный апостроф.** В `MessageFormat` апостроф начинает «цитату», и всё после него остаётся неформатированным:

```run
import java.text.MessageFormat
import java.util.Locale

fun main() {
    val english = Locale.ENGLISH
    println(MessageFormat("It''s {0}", english).format(arrayOf<Any>("ok")))
    println(MessageFormat("It's {0} and more", english).format(arrayOf<Any>("ok")))
}
```

```output
It's ok
Its {0} and more
```

Вторая строка потеряла апостроф и **подстановку**. Человек, который в админке напишет «We're glad to see {0}», получил бы сломанное предложение. Поэтому `OverlayBundle` ([OverlayBundle.kt](repo:src/main/kotlin/org/proanima/shelter/i18n/OverlayBundle.kt)) удваивает апострофы в отредактированных текстах для сообщений с аргументами: «A person typing "we're" must not make half of the sentence disappear».

### Тексты из админки поверх файлов: паттерн «декоратор»

Волонтёры могут править тексты страниц через админку. Но тексты, поставляемые с кодом, остаются «по умолчанию»: база хранит **только изменённое**. Для этого `OverlayBundle` накладывается поверх обычного набора сообщений:

```run
interface Messages {
    fun get(key: String): String?
}

class MapMessages(private val data: Map<String, String>) : Messages {
    override fun get(key: String) = data[key]
}

class Overlay(private val base: Messages, private val edited: Map<String, String>) : Messages {
    override fun get(key: String) = edited[key] ?: base.get(key)
}

fun main() {
    val shipped = MapMessages(mapOf("home.title" to "Pro Anima Volunteer Hub", "footer.text" to "Pro Anima"))
    val live = Overlay(shipped, mapOf("home.title" to "Volunteers of Pro Anima"))
    println(live.get("home.title"))
    println(live.get("footer.text"))
    println(live.get("nope"))
}
```

```output
Volunteers of Pro Anima
Pro Anima
null
```

У решения два следствия, зафиксированных в `docs/decisions.md`. Сайт, которого никто не редактировал, **байт в байт** совпадает с прежним, и никаких миграций не нужно. А текст, который не трогали, продолжает **следовать за кодом**: если разработчик улучшит перевод в файле, это увидят все.

## Склонение: где ломается ChoiceFormat

«2 года», «5 лет», «21 год»: в русском слово зависит от числа. Проект решает это формулой `ChoiceFormat` прямо в файле сообщений:

```properties
cat.age.years={0,choice,2#{0} года|5#{0} лет|21#{0} год|22#{0} года|25#{0} лет}
```

Запись читается: «от 2 включительно, до 5 — «года»; от 5 до 21 — «лет»; от 21 до 22 — «год»; от 22 до 25 — «года»; от 25 и выше — «лет»». Для возраста кошки от 2 до 24 лет всё правильно, и тесты проекта это проверяют (2, 5, 14, 22). Но формула **не цикличная**, а русская грамматика цикличная. Проверим:

```run
import java.text.MessageFormat
import java.util.Locale

fun main() {
    val pattern = "{0,choice,2#{0} года|5#{0} лет|21#{0} год|22#{0} года|25#{0} лет}"
    val format = MessageFormat(pattern, Locale.forLanguageTag("ru"))
    listOf(2, 5, 11, 21, 22, 25, 31, 32, 101).forEach { n ->
        println("$n -> ${format.format(arrayOf<Any>(n))}")
    }
}
```

```output
2 -> 2 года
5 -> 5 лет
11 -> 11 лет
21 -> 21 год
22 -> 22 года
25 -> 25 лет
31 -> 31 лет
32 -> 32 лет
101 -> 101 лет
```

Для 31, 32 и 101 результат неверен («31 год», «32 года», «101 год»). Это **известное ограничение**, а не баг в практическом смысле: кошки столько не живут. Но оно показывает общий урок: решение, корректное на области допустимых значений, нужно *знать* и *записать*. А если границы изменятся (например, строка пойдёт на счёт дней), решение придётся поменять.

### Правильное правило: категории множественного числа

Стандарт CLDR описывает для каждого языка набор категорий: в английском две (`one`, `other`), в русском четыре (`one`, `few`, `many`, `other`), в сербском похоже на русский. Для целых чисел в русском:

- `one`: заканчивается на 1, но не на 11 (1, 21, 31, 101);
- `few`: заканчивается на 2–4, но не на 12–14 (2, 22, 34);
- `many`: всё остальное (0, 5–20, 25–30).

:::step Шаг 3. when с тремя ветками
```kotlin
fun russianPlural(n: Int, one: String, few: String, many: String): String {
    val mod10 = n % 10
    val mod100 = n % 100
    return when {
        mod10 == 1 && mod100 != 11 -> one
        mod10 in 2..4 && mod100 !in 12..14 -> few
        else -> many
    }
}
```

## Многоязычные метаданные для поисковиков

В `<head>` каждой страницы ([Layout.kt](repo:src/main/kotlin/org/proanima/shelter/views/Layout.kt)):

```html
<link rel="canonical" href="https://shelter-volunteer.onrender.com/ru/cats">
<link rel="alternate" hreflang="ru" href="https://.../ru/cats">
<link rel="alternate" hreflang="en" href="https://.../en/cats">
<link rel="alternate" hreflang="sr" href="https://.../sr/cats">
<link rel="alternate" hreflang="x-default" href="https://.../ru/cats">
```

- **`canonical`**: «это основной адрес страницы». Адреса должны быть абсолютными, поэтому публичный адрес сайта вынесен в настройку `PUBLIC_BASE_URL`: когда у сайта появится свой домен, меняется одна переменная окружения.
- **`hreflang`**: «у этой страницы есть версии на других языках». Поисковик показывает человеку версию на его языке и не считает три страницы дублями.
- **`x-default`**: запасной вариант для тех, чей язык не в списке.
- Для страниц ошибок (`indexable = false`) вместо этого `noindex`: у них нет собственного адреса.

Для даты тоже важен язык: `displayItemDate` форматирует дату через `DateTimeFormatter.ofLocalizedDate(FormatStyle.LONG)` в локали страницы, а для сербского берётся `sr-Latn` (латиница). Тот же язык может писаться разными алфавитами, и сайт выбрал тот, что в повседневном ходу в Сербии.

## Дизайн для самого длинного языка

В дизайн-системе проекта записан принцип: **«Longest language wins»**: русские и сербские строки длиннее английских, поэтому ничего не должно зависеть от фиксированной ширины. Название пункта меню «Как помочь» самое длинное из пяти, и именно по нему подбирались размеры меню на телефоне (иначе пять пунктов не влезают в 360 пикселей). Проверять вёрстку только на английском значит оставить дефекты в двух других языках.

::::task Пробелы в переводах
Админка показывает, на каких языках не хватает перевода: для каждого языка, кроме русского, проверяется, есть ли запись, где русский текст есть, а текст на этом языке пуст. Напишите `translationGaps`.

```starter

fun translationGaps(texts: List<Text?>): List<String> {
    // TODO: languages (except "ru") for which some text has Russian but nothing in that language
    TODO()
}

fun main() {
    println(translationGaps(listOf(Text(ru = "Феликс", en = "Felix", sr = "Feliks"), null)))
    println(translationGaps(listOf(Text(ru = "Мила", en = "Mila"))))
```

:::solution
```run
data class Text(val ru: String? = null, val en: String? = null, val sr: String? = null)

private fun Text.valueIn(language: String): String? = when (language) {
    "ru" -> ru
    "en" -> en
    else -> sr
}

fun translationGaps(texts: List<Text?>): List<String> =
    listOf("ru", "en", "sr").filter { language ->
        language != "ru" && texts.any { text ->
            text != null && !text.ru.isNullOrBlank() && text.valueIn(language).isNullOrBlank()
        }
    }

fun main() {
    println(translationGaps(listOf(Text(ru = "Феликс", en = "Felix", sr = "Feliks"), null)))
    println(translationGaps(listOf(Text(ru = "Мила", en = "Mila"))))
    println(translationGaps(listOf(Text(ru = "Нами", en = " "), Text(en = "Fox"))))
}
```

```output
[]
[sr]
[en, sr]
```

Это упрощённая `translationGaps` из `AdminForms.kt`. Обратите внимание на третий случай: второй текст (`Fox` без русского) **не** считается пробелом: перевода нет, потому что нет оригинала. А пробел из пробелов (`" "`) считается пустым (`isNullOrBlank`).

::::task Почему пропало слово
Этот код должен напечатать «We're glad: 5 volunteers», а печатает что-то другое. Найдите причину и исправьте так, чтобы текст из админки не мог сломать предложение.

```starter
import java.text.MessageFormat
import java.util.Locale

fun format(pattern: String, count: Int): String =
    MessageFormat(pattern, Locale.ENGLISH).format(arrayOf<Any>(count))

fun main() {
    println(format("We're glad: {0} volunteers", 5))
}
```

:::solution
```run
import java.text.MessageFormat
import java.util.Locale

fun format(pattern: String, count: Int): String =
    MessageFormat(pattern.replace("'", "''"), Locale.ENGLISH).format(arrayOf<Any>(count))

fun main() {
    println(format("We're glad: {0} volunteers", 5))
}
```

```output
We're glad: 5 volunteers
```

Одиночный апостроф начинает «цитату» в `MessageFormat`, поэтому исходный код печатает `Were glad: {0} volunteers`. Исправление: удвоить апострофы перед форматированием. Заметьте, что так делать надо **только** для текста, который пришёл от человека и содержит подстановки. Файлы сообщений проекта пишутся для `MessageFormat` и уже содержат `''` там, где нужно.
:::

Q: Почему язык вынесен в адрес (`/ru/...`), а не определяется по `Accept-Language`?
- [ ] Так быстрее.
- [x] Адрес однозначно определяет версию: ссылкой можно поделиться, кэш и поисковики различают версии.
- [ ] Браузеры не присылают `Accept-Language`.
- [ ] Это требование Ktor.
E: Один адрес с разным содержимым вредит кэшированию, индексации и обмену ссылками.

Q: В `messages_sr.properties` нет ключа `nav.help`. Что покажет сербская страница?
- [ ] Исключение.
- [ ] Пустое место.
- [x] Текст из родительского (базового) файла сообщений, то есть английский.
- [ ] Сам ключ `nav.help`.
E: `ResourceBundle` ищет по цепочке от конкретной локали к базовому файлу.

Q: Почему `t()` создаёт `MessageFormat(pattern, locale)`, а не вызывает статический `MessageFormat.format`?
- [ ] Статический метод удалён.
- [x] Статический метод форматирует числа в локали машины; результат зависел бы от настроек сервера.
- [ ] Так медленнее.
- [ ] Чтобы поддержать сербский.
E: Явная локаль делает результат повторяемым на любой машине.

Q: Что не так с формулой `{0,choice,2#...|5#...|21#...|22#...|25#...}` для возраста?
- [ ] Она не компилируется.
- [x] Она не цикличная: для 31 даёт «лет» вместо «год», потому что русские окончания повторяются каждые десять и каждые сто.
- [ ] Она не поддерживает число 2.
- [ ] Она работает только для кошек.
E: Для возраста кошек (до 25–30) результат верен; но решение нужно знать, чтобы не применять его к неограниченным числам.

Q: Что даёт `hreflang` в `<head>`?
- [x] Поисковик знает, что страницы — версии одной и той же страницы на разных языках.
- [x] Человеку показывается версия на его языке.
- [ ] Браузер автоматически переводит страницу.
- [ ] Страницы объединяются в одну.
E: `hreflang` связывает версии, а не переводит; три страницы остаются тремя.

Q: Какое свойство даёт схема «база хранит только изменённые тексты, остальное из файлов»?
- [ ] Быстрее работает база.
- [x] Сайт, который никто не редактировал, совпадает с прежним без миграции, а нетронутые тексты следуют за улучшениями в коде.
- [ ] Тексты нельзя вернуть к исходным.
- [ ] Не нужны файлы сообщений.
E: Это паттерн «декоратор» поверх набора сообщений: слой правок накладывается на исходные тексты.

## Итоги

- Язык в адресе, одинаковая структура адресов, переключатель меняет только префикс.
- Две цепочки запасных языков: сообщения интерфейса и данные; недостающий перевод не должен ломать страницу.
- Форматирование с аргументами: явная локаль, осторожность с апострофами, правила множественного числа вместо диапазонов.
- Метаданные: `canonical`, `hreflang`, `x-default`, абсолютные адреса через настройку.
- Проектируйте под самый длинный язык.
